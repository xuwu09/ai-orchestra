# 讨论协议库（Discussion Protocols）

多 AI 讨论的结构化协议。普通互审（SKILL.md 第 4 步）解决「方案细化」，
本协议库解决「多观点归并、分歧裁决、质量收敛」——**协议与站点/成员无关**，
任何通道（ChatParty 群发/讨论、foreign-cli 五站、DSH 子代理、组长本人）都可执行。

> 出处致谢：本协议借鉴 [dsh-plugin-roundtable](https://github.com/9931666/dsh-plugin-roundtable)（9931666，MIT）的
> 汇聚网关 / 观点拆分 / 三态表态 / 闭环复审 / 预算熔断机制，按 ai-orchestra
> 无宿主、浏览器矩阵的特点改写；防风控节流参数取自
> [dsh-deepseek-web-login](https://github.com/cv-superding/dsh-deepseek-web-login)（Apache-2.0）的实测值。

## 三种讨论模式

| 模式 | 适用 | 规则 | 终止 |
|---|---|---|---|
| **主持人统筹**（默认） | 方案互审（SKILL.md 第 4 步） | 一切发言经组长转达归并，组长语义仲裁 | 双方无实质分歧 |
| **平等互辩** | 开放式议题（技术选型之争、选题方向） | 成员直达互辩（消息互相引用反驳），组长退居发牌+计时+裁判 | 轮数预算超限自动收场 |
| **红队评审** | 方案定稿后、派干活组前（高价值任务） | 指定 1~2 位成员**只挑毛病、不给替代方案** | 复审通过或达轮上限 |

选平等互辩时必须先定预算（见下），否则自由辩论无收敛点。

## 汇聚网关（round2 的正确姿势）

把多位成员的发言喂回下一轮讨论时，**禁止全文拼接**（token 爆炸，且曾出过
round2 上下文空转事故）。正确流程：

1. **观点拆分**：每位成员的一条发言拆成多条独立观点，每条带
   维度标签 + 原文引用 + 出处站 + 证据
2. **去重归并**：相同观点合并，标注「N 站共识 / 单站孤立」
3. **分维度摘要**后再生成 round2 prompt

观点拆分优先用 LLM（组长自己做即可）；LLM 不可用时**本地兜底**——按
「观点 1 / 观点 2 …」或编号段落结构切分，零 token，绝不整段糊在一起。

证据分级：bug/代码类缺陷附**可复现步骤**；设计类缺陷附**论证链**
（不强制伪复现）。

## 红队评审闭环

```
定稿方案
→ roundtable_start：记录「问题 + 方案」（首轮 review=1）
→ 红队发言（只挑毛病、不给替代方案）
→ 观点拆分 → 每条观点一张卡
→ 三态表态（组长/用户逐条）：支持 / 驳回（必填理由）/ 取消
→ 主笔按「支持」项修订方案（附修订说明）
→ 复审（review+1）：只核对上一轮已认定缺陷是否修复，不重开全案
→ 通过 → done；不通过 → 下一轮复审
```

- **maxReviewPass = 3**（首轮 + 最多 2 次复审），超上限必须用户显式批准——防无限循环
- 已认定数只计「支持」；**认定缺陷 ≥ 3 → 提示「建议重新协商方案」**
- 驳回理由必须回传给主笔（修订时逐条回应「为何驳回」）

## 预算熔断

- 讨论开跑前定两预算：**最大轮数**（平等互辩默认 3、互审常规 3~5）与
  **发言字数预算**（可选，粗估即可——是「说了多少」的刻度，不是成本表）
- 超限**自动闭麦**，转汇总收场；要继续必须用户显式加预算
- 轮次明显空转（连续两轮无新增发现）组长可提前叫停裁决

## 人类决策暂停

出现以下任一情况，组长出**决策卡片**并暂停讨论：
- 分歧无法归并（两轮仍各执一词）
- 红队认定缺陷 ≥ 3
- 触及不可逆决策（选型、花钱、对外发布）

决策卡片格式：议题 + 方案 A/B(+C) + 每案一句核心理由 + 组长倾向（可无）。
用户拍板后结果写回讨论记录再继续。

## 落盘与导出

- 讨论全程 **append-only** transcript（`<项目目录>/transcript-<日期>-<议题>.md`
  或 jsonl），禁止回写历史轮次
- 讨论结束一键导出 **export.md**：元数据头（议题/时间/参与成员/模式/轮数）/
  议题 / 决策记录 / 逐轮发言 / 评审记录（观点×表态×理由×修订对照）
- 用途：自媒体文稿底稿、贴 issue、复盘、golden 样本对照
- jsonl 落盘用**原子写**（同目录 tmp + rename），读取遇坏行返回
  malformed 计数如实上报，不静默丢弃

## 防风控节流（实测参数，来源 web-login 项目）

- **同一站点**连续请求：随机间隔 **2000~4000ms**——固定间隔方差≈0 本身就是
  「定时器特征」；实测双窗口并发 6 分钟即触发 1 天临时封禁
- 群发跨站无此约束（不同站独立），但**同一站重发/讨论多轮必须遵守**
- 禁止并发轰同一站；对站方所有自动化保持「单人节奏」
- **「发送成功」≠「服务端接受」**：URL 跳转只证明前端提交，回读
  （extract）确认回答区出现内容才算闭环；回答区出现拒绝/受限文案 =
  服务端拒绝（受限状态只能从生成被拒学到，只读探活探不出）
- 429/频控响应带 retryAfter 时交给上层重试策略，不立即硬重试

## 合规审查清单（2026-09-18 实战加）

> 来源：教育产品页实战——10 顾问全员同话术评审，无一拦截「平均提分 27 分 / 就业保障 / 薪资提升 40%」类广告法违禁文案。全员评审 ≠ 全维度覆盖，**合规必须专职专审**。

**触发条件**：成品面向对外发布（营销页 / 商业文案 / 宣传物料 / 落地页），交付前强制过一遍；评审派单时指定 1 名顾问专职持此清单审。

**通用清单（广告法红线）**：

| 类别 | 违禁示例 | 合规替代 |
|---|---|---|
| 承诺效果 | 「平均提分 27 分」「保过」「包就业」 | 「学员进步案例」「历史学员反馈」（附「效果因人而异」） |
| 承诺收益 | 「薪资提升 40%」「躺赚」「稳赚」 | 「优秀学员直推面试」（不承诺数字） |
| 绝对化用语 | 「最好」「第一」「国家级」「顶级」 | 「行业领先」等可证表述，或删 |
| 数据无源 | 「98.6% 满意度」「12000+ 学员」 | 标注统计口径与时间，或改为示意（demo 标注「示例数据」） |
| 权威背书 | 假冒「国家级机构合作」「名校授权」 | 有授权文件才可写 |

**行业红线**：教育（不得对升学/考试通过作保证性承诺）、医疗（诊疗效果宣传受专项监管）、金融（收益承诺违规）。触发行业红线时整体升级为人类决策暂停。

**成品遗留物检查**：模板占位符（「XXXXXXXX」「示例文案」）、`href="#"` 死链、与正文表述脱节的引用——demo 可留但须集中标注「上线前待换清单」。

## 多轮打磨协议（轮次结构与收敛判据，2026-09-18 加）

> 来源：DSH 实测——编排者把任务包发一轮收意见就当「讨论完了」，直接开工。多审原则（3 轮起步）写了但没长牙，本节把收敛做成可检查的动作。

**轮次结构**（方案/成品类任务）：

- **第 1 轮（发散）**：任务包发全员（`broadcast`），只收意见不动工；组长按维度归并（见下节评审维度分配表）
- **修订轮**：主笔按意见出修订稿，**逐条标注处置**（采纳→改了哪里；驳回→为什么）
- **第 2 轮（复核）**：修订稿**只发回提过意见的顾问本人**，问「你提的问题改了没？新版还有什么问题？」——不是泛泛重发全员
- **第 3 轮起（如需）**：只围绕仍有分歧的点小范围讨论，不重开全场
- **定稿**：收敛判据全过 → 主笔终稿自检（实现者视角）→ 进干活组

**收敛判据（全部满足才许定稿）**：

1. 上一轮意见 **100% 有处置记录**（含驳回+理由）
2. 本轮**无新增实质意见**（同意见复述不算；同一问题的新例证算）
3. 意见提出者**本人确认过修订稿**（确认 = 明确回复「没问题/可以」，沉默不算）
4. **回复率 ≥60%**（broadcast 对账 missing 清零或已催收）
5. **合规维度专职审过**（合规审查清单节）

**假收敛黑名单**（出现即不算收敛，必须补轮）：

- 「发了没人回 = 同意」——沉默不是确认
- 「有人说了 OK 但没针对修订稿」——确认必须指向修订稿本身
- 「第 1 轮意见少 = 没问题」——可能只是没看完/没读懂任务包
- 「赶时间跳过复核轮」——时间压力不是理由，可以砍范围，不砍轮次

**熔断**：总轮次上限 4~5 轮（大型任务）；到顶仍有实质分歧 → 汇总分歧点**升级人类决策暂停**。轮次空转（连续 2 轮无新增发现）组长可提前叫停（多审原则既有规则）。

## 评审维度分配表（2026-09-18 实战加）

> 来源：教育产品页实战——全员同话术评审的第二个盲区：所有人都在挑文案与结构，没人从受众转化视角看，也没人核对数据来源。**维度互斥 + 专职专审**才覆盖得住。

**派单原则**：发布评审任务时按维度分派，每个维度至少 1 名顾问，**同一顾问不兼多维度**（兼了就会复现「同话术盲区」）；顾问回意见必须带维度标签（如 `[合规]`），无标签意见视为普通发言不计入评审闭环。

| 维度 | 审什么 | 派给谁 | 否决权 |
|---|---|---|---|
| 结构 | 逻辑完整性 / 论据支撑 / 篇幅节奏 | 方案组逻辑强项顾问 | 无 |
| 合规 | 广告法红线 / 行业敏感词 / 遗留物（见上节清单） | **专职 1 名**，绝不兼任 | **一票否决** |
| 技术 | 可行性 / 边界条件 / 数据与引用可溯源 | 代码组或有技术背景顾问 | 无 |
| 转化 | 受众视角 / 行动号召 / 标题与钩子 | 运营 / 营销背景顾问 | 无 |

**流程**：任务包按维度拆派单 → 各顾问带标签回意见 → 组长归并为 review.md（按维度分组）→ 合规否决项整改后**仅合维度复审**（不重开全场）。

## 任务包落盘协议（transcript 绑定）

> 来源：DSH 实测——任务包只在聊天流里，评审意见散落各站会话页，事后对不上「哪条意见对应哪个任务版本」。**先落盘，再派发**。

**目录结构**（组长在开工时创建，随场演进）：

```
discussions/<YYYYMMDD-HHMM>-<主题slug>/
├── task.md          # 任务包原文，落盘后不可变；改动 = 新目录（版本演进可见）
├── transcript.jsonl # 每行一条：{"ts","site","kind","content"}
│                    #   kind ∈ task|reply|review|summary
│                    #   ts 用发/收时刻；site 是站点 key（doubao/qwen/…）
├── review.md        # 评审意见归并（按维度分组，每条注站点与 transcript 行号）
└── export.md        # 全场导出：任务包摘要 + 分组意见 + 结论 + 遗留项
```

**规则**：
1. 任务包派发**前**先写 task.md（引用时给出文件路径，站点收到的全文即该文件内容）
2. 每收到一站回复，追加一行 transcript.jsonl（append-only，不回改）
3. 评审意见必须引用 transcript 行号或站点 key，无法溯源的意见不入 review.md
4. 成品交付时 export.md 随附——验收门（SKILL.md）拿它当输入
5. broadcast 对账结果（sent/verify/suspicious/missing）也落一行 kind=summary，缺站补发后补记录
