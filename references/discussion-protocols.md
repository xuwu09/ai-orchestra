# 讨论协议库（Discussion Protocols）

多 AI 讨论的结构化协议。普通互审（SKILL.md 第 4 步）解决「方案细化」，
本协议库解决「多观点归并、分歧裁决、质量收敛」——**协议与站点/成员无关**，
任何通道（ChatParty 群发/讨论、foreign-cli 五站、DSH 子代理、组长本人）都可执行。

> 出处致谢：本协议借鉴 [dsh-plugin-roundtable](https://github.com/9931666/dsh-plugin-roundtable)（9931666，MIT）的
> 汇聚网关 / 观点拆分 / 三态表态 / 闭环复审 / 预算熔断机制，按 ai-orchestra
> 无宿主、浏览器矩阵的特点改写；防风控节流参数取自
> [dsh-deepseek-web-login](https://github.com/cv-superding/dsh-deepseek-web-login)（Apache-2.0）的实测值。

## 三种讨论模式

| 模式 | 适用 | 规则 | 终止 |
|---|---|---|---|
| **主持人统筹**（默认） | 方案互审（SKILL.md 第 4 步） | 一切发言经组长转达归并，组长语义仲裁 | 双方无实质分歧 |
| **平等互辩** | 开放式议题（技术选型之争、选题方向） | 成员直达互辩（消息互相引用反驳），组长退居发牌+计时+裁判 | 轮数预算超限自动收场 |
| **红队评审** | 方案定稿后、派干活组前（高价值任务） | 指定 1~2 位成员**只挑毛病、不给替代方案** | 复审通过或达轮上限 |

选平等互辩时必须先定预算（见下），否则自由辩论无收敛点。

## 汇聚网关（round2 的正确姿势）

把多位成员的发言喂回下一轮讨论时，**禁止全文拼接**（token 爆炸，且曾出过
round2 上下文空转事故）。正确流程：

1. **观点拆分**：每位成员的一条发言拆成多条独立观点，每条带
   维度标签 + 原文引用 + 出处站 + 证据
2. **去重归并**：相同观点合并，标注「N 站共识 / 单站孤立」
3. **分维度摘要**后再生成 round2 prompt

观点拆分优先用 LLM（组长自己做即可）；LLM 不可用时**本地兜底**——按
「观点 1 / 观点 2 …」或编号段落结构切分，零 token，绝不整段糊在一起。

证据分级：bug/代码类缺陷附**可复现步骤**；设计类缺陷附**论证链**
（不强制伪复现）。

## 红队评审闭环

```
定稿方案
→ roundtable_start：记录「问题 + 方案」（首轮 review=1）
→ 红队发言（只挑毛病、不给替代方案）
→ 观点拆分 → 每条观点一张卡
→ 三态表态（组长/用户逐条）：支持 / 驳回（必填理由）/ 取消
→ 主笔按「支持」项修订方案（附修订说明）
→ 复审（review+1）：只核对上一轮已认定缺陷是否修复，不重开全案
→ 通过 → done；不通过 → 下一轮复审
```

- **maxReviewPass = 3**（首轮 + 最多 2 次复审），超上限必须用户显式批准——防无限循环
- 已认定数只计「支持」；**认定缺陷 ≥ 3 → 提示「建议重新协商方案」**
- 驳回理由必须回传给主笔（修订时逐条回应「为何驳回」）

## 预算熔断

- 讨论开跑前定两预算：**最大轮数**（平等互辩默认 3、互审常规 3~5）与
  **发言字数预算**（可选，粗估即可——是「说了多少」的刻度，不是成本表）
- 超限**自动闭麦**，转汇总收场；要继续必须用户显式加预算
- 轮次明显空转（连续两轮无新增发现）组长可提前叫停裁决

## 人类决策暂停

出现以下任一情况，组长出**决策卡片**并暂停讨论：
- 分歧无法归并（两轮仍各执一词）
- 红队认定缺陷 ≥ 3
- 触及不可逆决策（选型、花钱、对外发布）

决策卡片格式：议题 + 方案 A/B(+C) + 每案一句核心理由 + 组长倾向（可无）。
用户拍板后结果写回讨论记录再继续。

## 落盘与导出

- 讨论全程 **append-only** transcript（`<项目目录>/transcript-<日期>-<议题>.md`
  或 jsonl），禁止回写历史轮次
- 讨论结束一键导出 **export.md**：元数据头（议题/时间/参与成员/模式/轮数）/
  议题 / 决策记录 / 逐轮发言 / 评审记录（观点×表态×理由×修订对照）
- 用途：自媒体文稿底稿、贴 issue、复盘、golden 样本对照
- jsonl 落盘用**原子写**（同目录 tmp + rename），读取遇坏行返回
  malformed 计数如实上报，不静默丢弃

## 防风控节流（实测参数，来源 web-login 项目）

- **同一站点**连续请求：随机间隔 **2000~4000ms**——固定间隔方差≈0 本身就是
  「定时器特征」；实测双窗口并发 6 分钟即触发 1 天临时封禁
- 群发跨站无此约束（不同站独立），但**同一站重发/讨论多轮必须遵守**
- 禁止并发轰同一站；对站方所有自动化保持「单人节奏」
- **「发送成功」≠「服务端接受」**：URL 跳转只证明前端提交，回读
  （extract）确认回答区出现内容才算闭环；回答区出现拒绝/受限文案 =
  服务端拒绝（受限状态只能从生成被拒学到，只读探活探不出）
- 429/频控响应带 retryAfter 时交给上层重试策略，不立即硬重试
