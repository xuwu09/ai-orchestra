# 成员档案（模板）

> **使用方法**：把本文件复制为 `references/capabilities.md`（同目录），按你自己的成员清单填写。
> 本仓库只附带模板，不含任何个人成员档案——你的真实档案不要提交到公开仓库。
> 每个成员档案建议字段：**定位 / 强项 / 短板 / 适用 / 不适用 / 调用方式 / 约束 / 状态**。

派发前查此档案。额度与功能会过期，与现场不符时以官方文档为准，并提醒用户更新本档案。
**状态标记**：现役（默认调用）/ 候补（已点名可入组，待试跑）/ 已移出（留档备查，不再派任务）。
新成员入组：用户点名 → 核对 SKILL.md 角色准入 → 在此建档（状态=候补）→ 小任务试跑 → 转现役。

## 组长层（准入：能改本地文件 + 派单收产物 + 实测验收；同一时间只有一个组长）

### <你的组长客户端> —— 现役组长
- **定位**：当前会话智能体：派单、监控、验收、交付。直接拥有文件系统、shell、任务管理、记忆。
- **强项**：全流程编排、产物实测验收（读文件/跑脚本/无头浏览器冒烟）、质量把关、最终交付。
- **约束**：（按实际填写，如：沙箱拉起的 GUI 进程易被回收、不能替用户操作第三方客户端内部等）

### 组长候补（用户点名即可接任，交接清单见 SKILL.md「更换组长」）
| 成员 | 类型 | 备注 |
|---|---|---|
| Codex | CLI/IDE agent | 能读写本地文件、跑 shell；担任组长后不再兼任干活 |
| Claude Code | CLI/IDE agent | 同上 |
| （其他） | 任何满足组长准入的客户端 | 用户点名即入组 |

## 顾问组（写具体方案 + 多轮互审 + bug 修复方案；不下场干活；不需要本地文件写权限）

> 协作方式：主笔出完整可执行的具体方案初稿 → 顾问之间多轮往返互审（以「无实质分歧」为退出条件）→ 主笔完善成最详细版定稿。定稿标准：干活组拿到方案后不需要再做任何设计决策。

### <主笔顾问 A>（如：千问/通义类）—— 现役
- **强项**：长文档、多模态、免费额度大 → 技术/文档/数据向方案主笔首选。
- **调用方式**：（按实际填写：CDP 客户端直连 / OpenCLI 网页 / 剪贴板接力；编辑器不认 JS 合成 Enter 的必须走 CDP 原生 Input 管线）

### <主笔顾问 B>（如：豆包类）—— 现役
- **强项**：产品/语感/选题向主笔、轻素材生成。
- **调用方式**：（同上按实际填写）

### <网页站聚合通道>（可选，如 ChatParty 类多站应用）—— 现役/候补
- **定位**：桌面应用内多个已登录网页 AI 按额度分组——**搜索组（无限额）**资料搜集/初筛/时效核查；**方案组（有限额）**只干核心方案活。
- **通道降级**：用户不愿安装该应用、或其运行影响前台工作时 → 改走 OpenCLI 网页路线逐站替代。
- **工具**：见 `tools/chatparty/`（登录看门狗 + 试跑脚本，配合 CDP 使用）。
- **关键坑**：①各站输入框选择器不同，通用兜底=`[contenteditable=true], textarea` 取第一个可见的；②脚本里请求 CDP 必须**禁代理**（`ProxyHandler({})`），否则本机回环请求会被系统代理劫持超时；③派给站内顾问的文本同样要人话化（防 AI 检测，规则与顾问组一致）。

### 顾问候补（用户点名即可上岗，互审可任意组合）
| 成员 | 强项方向 | 最适合派 | 派发提示 |
|---|---|---|---|
| GPT 类 | 通用推理/技术方案/长文 | 技术方案主笔或互审 | 外网成员走 web-proxy 通道；额度有限合并提问 |
| Grok 类 | 语感/选题/时效查证 | 常规轨按强项参与 | 回复可能需登录 |
| Gemini 类 | 多模态/百万 token 级长上下文 | 超长文档审读 | 超长材料唯一不截断的选择 |
| （更多按需补充） | | | |

**外网成员双轨策略（可选）**：①常规顾问轨=按强项正常参与；②补全轨=国内 AI 缺口时补位，强制「先国内尝试 → 缺口清单 → 外网补全 → 国内复审」流程。硬红线：仅限合法合规内容，不合规请求直接拒派。

## 特殊工作组（与干活组同级；平时闲置，特定任务才启用；组长或顾问组均可直接对接）

### 本机执行类（可选，如 Marvis / ima 等）
- **启用时机**：任务涉及「在本机真实动手」且组长不便直接做时（大批量文件整理、系统排查、跨端接力）；或知识库沉淀/素材入库/长报告播客生成。
- **约束**：涉隐私文件优先本地隐私模式；高风险操作（删除/改设置/支付）默认要求用户确认；生成内容要求「严格基于知识库」防幻觉。

### 创意组（生图生视频 + 设计，可按需合并或分设）

> **专属通道登记（可选）**：各成员的专属 MCP/CLI 先登记地址不安装，用户点名需要时再装。安装前先核验地址有效性（多为第三方开源项目）。
>
> | 成员 | 专属工具 | 类型 | 地址 | 状态 |
> |---|---|---|---|---|
> | （示例）即梦AI | dreamina-cli | CLI | <github 链接> | 未安装 |
> | （示例）Figma | figma-cli | CLI | <github 链接> | 未安装 |
>
> 未安装时的默认通道：网页 → opencli browser / 剪贴板接力；本地程序 → CLI-Anything。

**派发总则（「网页 vs 程序」二分）**：网页工具 → opencli browser 控制；本地程序 → CLI-Anything 控制（API/命令行/CDP 按程序暴露的接口选）。产物回传本地路径，组长核验（尺寸/内容/风格 vs 方案要求）后交用户。

成员档案按「强项/短板/适用/不适用/调用」五段式填写（示例见本仓库 README 的架构说明）。

### 代码组（准入同干活组=能修改本地文件；铁律同干活组）

> 定位：干活组的扩展池，按任务特征/用户点名分流，未点名默认走干活组现役成员。共享「一客端一角色」原则。
> **组长资格**：代码组全员均可担任组长——点名即接任，交接清单走 SKILL.md「更换组长」流程；当组长期间不再兼任代码组/干活组岗位。

成员档案示例维度：CLI+IDE 双形态 / goal 模式长任务 / 长上下文理解 / IDE 内 agent / 开源终端 agent 多模型可配……按实际成员填写。

## 分工决策表（派发前查）

| 任务特征 | 首选 | 理由 |
|---|---|---|
| 方案起草（技术/文档/数据向） | 强推理类顾问主笔 + 其他顾问互审 | 免费/廉价额度承担，多轮互审到最详细版 |
| 方案起草（语感/选题/产品向） | 语感类顾问主笔 + 其他顾问互审 | 方向互换 |
| 制作实现（编码/建站/成稿） | 干活组本地直跑 | 直接落盘 + 组长实测验收闭环 |
| bug 修复 | 顾问组出修复方案 → 干活组执行 | 方案与实现分离 |
| 产物验收 | 组长实测 → 用户终验 | 组长不轻信交付说明 |
| 资料搜集/时效核查 | 网页站聚合·搜索组（无限额） | 产出资料包交方案组 |
| 纯文字出品 | 快车道：搜索组集资料 → 方案组讨论 → 指定一位定稿交付 | 跳过干活组 |
| 生图/生视频（轻量） | 组长内置生图生视频能力 | 快、免费 |
| 生图/生视频（高质量/工作流） | 创意组（网页 vs 程序二分选通道） | 按质量/一致性/可复现要求选成员 |
| UI 设计稿/原型 | 创意组·设计方向 | 产出作为「设计附录」并入定稿 |
| 编码（用户点名代码组） | 代码组成员 | 规则同干活组 |
| 隐私敏感批处理 | 本地干活组 | 数据不出本机 |
