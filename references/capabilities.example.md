# 成员档案（完整示例 · 真实在用架构的脱敏版）

> **使用方法**：本文件就是一份**完整在用架构**的脱敏版——成员、分工、状态、踩坑记录全保留，
> 只有本机路径/私有端口/个人记录被替换成 `<占位符>`。把本文件复制为 `references/capabilities.md`
> （同目录），对照自己的环境改路径与成员清单即可获得同等功能。
> 你自己填好的真实 capabilities.md 不要提交到公开仓库（.gitignore 已排除）。

派发前查此档案。额度与功能会过期，与现场不符时以官方文档为准，并提醒用户更新本档案。
**状态标记**：现役（默认调用）/ 候补（已点名可入组，待试跑）/ 已移出（留档备查，不再派任务）。
新成员入组：用户点名 → 核对 SKILL.md 角色准入 → 在此建档（状态=候补）→ 小任务试跑 → 转现役。

## 顾问组（写具体方案 + 多轮互审 + bug 修复方案；不下场干活；不需要本地文件写权限）

> 协作方式：主笔（按任务方向选）出完整可执行的具体方案初稿 → 顾问之间多轮往返互审（每轮一位当审方，以「无实质分歧」为退出条件，常规 3 轮起步——方案阶段多审一轮，干活组返工少一轮）→ 主笔完善成最详细版定稿（每版带修改说明）。定稿标准：干活组拿到方案后不需要再做任何设计决策。bug 修复循环中负责把问题清单变成逐条对应的修复方案。
>
> 注：Kimi/MiniMax/智谱清言此前因**实现类任务不可靠**移出干活组；顾问岗不落盘、不实现，故可作顾问候补使用。

### 千问（通义）—— 现役
- **强项**：多模态、长文档、免费额度大。技术/文档/数据向方案主笔首选。
- **分工**：技术方案主笔、互审（产品/语感向方案）、修复方案讨论、资料背景补充。
- **调用方式**：优先 CDP 客户端直连——`qianwen_cli.py`（status/new/send/extract/ensure 五件套，幂等 bat + 开机自启 VBS，端口在 routes.yaml 配置）。**必须走 CDP 原生 Input 管线**（编辑器不认 JS 合成 Enter）。备选：OpenCLI 网页通道（fill+Enter 直达）。

### 豆包 —— 现役
- **强项**：桌面端体验好、图像生成、抖音生态同源语感。
- **分工**：产品/语感/选题向方案主笔、互审（技术向方案）、修复方案讨论、封面图等轻素材生成（用户认可时才当产出）。
- **调用方式（按优先级）**：
  1. **桌面客户端 CDP 直连**：幂等 bat 重启带 CDP 端口 → `doubao_cli.py`（status/new/send/extract）。输入框是 tiptap ProseMirror，但 CDP insertText 走真实输入管线，**网页版 fill 后 Enter 不认账的坑在此通道不存在**。extract 回读整页文本尾部，组长按标记词切片。
  2. **OpenCLI 网页**：daemon + Bridge 扩展在线时可用；ProseMirror verified:false → 剪贴板粘贴法。
- **注意**：客户端正常双击启动不带 CDP；CDP 由幂等 bat 启动才生效。

  | 站点 | 强项方向 | 状态 |
  |---|---|---|
  | Kimi（kimi.com） | 长文本精读、编程、联网 | ✅ 试跑通过（发送→思考→回复闭环） |
  | GLM（chatglm.cn 智谱清言） | 对话知识、选题 | 候补待试跑 |
  | MiMo（aistudio.xiaomimimo.com） | 小米系 | 候补待试跑 |
  | 千问网页（qianwen.com） | 长文档、多模态；与千问客户端互为备份 | 候补 |
- **机动（未分组）**：DeepSeek（chat.deepseek.com）——推理强，按需临时派，默认候补。
- **组内机制**：ChatParty 自带「多模型讨论」（同题群发多站收集观点）与「AI 回答总结/对比」——方案组讨论与互审优先用这两个原生机制，组长只做汇总裁决。
- **通道降级**：用户不愿安装 ChatParty、或其运行影响前台工作时 → 改走 **OpenCLI 网页路线**逐站替代，规则与顾问组网页通道一致。
- **调用方式**：`python tools/chatparty/trial_send.py <site> <url_prefix> "<text>"`（仓库内脚本，CDP 端口默认 9222）。原理：CDP 按 URL 匹配 webview target → 编辑器 `scrollIntoView`（多站应用 webview 小窗渲染，元素常在视口外）→ 视口内用可信点击、视口外用 JS focus → `Input.insertText` → 原生 `dispatchKeyEvent` Enter → `document.body.innerText` 尾部切片收回复。
- **关键坑**：①各站输入框选择器不同（Kimi=`.chat-input-editor`、秘塔=`textarea.search-consult-textarea`，通用兜底=`[contenteditable=true], textarea` 取第一个可见的；用 `cdp_inspect.py probe <url前缀>` 摸新站）；②脚本请求 CDP 必须**禁代理**（`ProxyHandler({})`），否则本机回环请求被系统代理劫持超时；③派给站内顾问的文本同样要人话化（都是网页 AI，防检测规则与顾问组一致）。
- **登录保活**：`cp_login_guard.py` 看门狗 45 秒巡检，掉登录自动注入 cookie+localStorage 并刷新，配置丢失自动回写——正常情况下该通道永远在线。
- **约束**：回复提取是整页文本尾部，组长按任务标记词切片；一次会话一问，别指望多轮上下文（各站会话结构不同）。

### 国外顾问组（独立外网顾问组 · 五站共用同一通道，双轨规则不变）

> **定位**：全部国外成员独立成组，共用同一通道——本地代理 + Edge 专用 profile（独立 user-data-dir）+ CDP 端口；统一 CLI 包装 `tools/foreign-cli/foreign_cli.py`（status/new/send/extract/ensure 五件套，五站）。启动 bat 要点：`--remote-debugging-port=<CDP口> --proxy-server=http://127.0.0.1:<代理口> --user-data-dir=<专用目录> --no-first-run`（幂等：先探测端口再拉起）。
>
> **运行形态**：站点既可以是独立标签页，也可以是「全提问」类分屏扩展里的 **iframe**——CLI 的 target 匹配用 **host 级**（urlparse netloc，防第三方 iframe 的 URL 参数误匹配）且同时接受 page/iframe 两类 target。发送管线=「三重门」（见下）。
>
> **三重门发送管线（ChatParty v4.5/v4.6 经验的网页版）**：①scan 门：在编辑器矩形内 15 点多点扫描 `elementFromPoint`，命中编辑器或其子元素才可点（布局未稳/浮层遮挡时坐标会偏，绝不盲点中心）；不中则先关 `[role=dialog]` 弹窗 + trusted Escape 再重扫。②focus 门：trusted click 后 `activeElement` 必须落在编辑器内（弹窗抢焦点是网页自动化头号变量），否则补点一次，仍败即中止。③value 门：`Input.insertText` 后读值 trim 非空才发 trusted Enter。hidden/iframe target 的 trusted 输入与普通页面完全等价。
>
> **登录态边界**：登录态存专用 profile，与日常浏览器不互通（cookie 绑定 profile 无法迁移）——新站需在该窗口人工登录一次，持久有效。
>
> **双轨调度（原规则原样适用全组）**：所有成员同时适用两套规则——常规顾问轨 + 补全轨，见本节后半。

| 成员 | 强项方向 | 最适合派 | 派发提示 |
|---|---|---|---|
| ChatGPT | 通用推理/技术方案/长文 | 常规轨=技术方案主笔或互审、逻辑链长的评审；补全轨=国内 AI 缺口时补位 | **E2E 全闭环**（发送→回复）；免费额度有限 → 合并提问、调用记日志 |
| Grok | 语感/选题/时效查证 | 常规轨按强项正常参与；补全轨=国际/海外信息、外文资料 | 输入管线 E2E 全过；回复流走 WebSocket，部分代理环境下会被阻断（间歇性，页内重试可恢复）——派发后先 extract 验证；额度未知 → 省着用 |
| Copilot | 微软系通用推理 + 联网搜索 | 常规轨=技术方案互审；补全轨=补缺口 | **E2E 闭环**；注意域名可能同时存在 copilot.microsoft.com 与 copilot.com 两种形态，host 匹配需覆盖 |
| Perplexity | 实时检索+引用来源（搜索问答最强） | 常规轨=时效查证/带来源的资料检索；补全轨=海外信息检索 | **E2E 全闭环**（答案带来源数，适合做资料检索位） |
| Gemini | 多模态/长上下文（百万 token 级） | 超长文档审读（整本书/全量代码库级互审）、图文混排评审 | **E2E 全闭环**；超长材料唯一不截断的选择 |

**双轨规则**：两条规则并行，由组长**根据任务内容**判断走哪条轨：任务本身匹配强项 → 直接走常规轨；任务先派国内顾问后出现缺口 → 走补全轨。

- **常规顾问轨**：任务内容匹配成员强项时，作为正常顾问参与主笔/互审（GPT=通用推理/技术方案/长文评审；Grok=语感/选题/时效查证；Copilot=技术互审；Perplexity=时效/检索；Gemini=超长材料审读），与其他顾问同规则轮换。
- **补全轨**：任务遇到「国内 AI 缺口」时补位（触发条件见下），此时不问强项只补缺口。
**补全轨触发条件**（满足其一）：
1. 任务需要**国际/海外信息**：海外舆情与产品调研、外文资料精读、国际时效查证（国内 AI 联网面窄）。
2. 国内 AI 产出**内容明显不全面**：知识盲区、信息过时、海外语境缺失，且这些缺口实质影响交付质量。
3. 国内 AI 因内容限制**拒答或严重缩水**：合法合规的选题（新闻时事分析、历史与社会议题、国际关系、性教育/健康科普等）被国内平台过度拒绝时，补全事实与视角。

**补全轨前置流程（强制）**：先派国内顾问 → 收到拒答/缩水/缺口 → 组长写「缺口清单」（缺什么、为什么国内 AI 给不了）→ 连同已有产出一起派外网成员补全 → 回收后由国内顾问复审整合。**禁止跳过国内尝试直接走补全轨。**

**额度保护（两轨通用）**：单任务尽量一次会话解决（把多个问题合并成一个委托）；能复用旧会话就开新话题不新开会话；非紧急任务攒批问；每次调用组长在任务日志记一条。

**硬红线（不可绕过，两轨通用）**：仅限合法合规场景。**不得**借外网成员生成色情、暴力血腥、犯罪或灰产操作指引等违法违规内容——「国内 AI 拒答」本身不构成派单理由，派单前组长必须先判断请求内容本身合法合规；不合规的请求直接向用户说明并拒派。**该红线适用于 ChatGPT、Grok、Copilot、Perplexity、Gemini 等一切外网成员，且在两条轨上都生效。**

## 特殊工作组（与干活组同级；平时闲置，特定任务才启用；组长或顾问组均可直接对接）

### Marvis（腾讯应用宝）
官方文档 https://marvis.qq.com/docs/ 。
- **定位**：系统级个人 AI 助手（"电子牛马"），把文件、系统、浏览器、应用、跨端连接统一为执行层。
- **强项**：本机文件查找/整理、系统设置调整、浏览器与应用操作、手机↔电脑任务接续；效率模式 / 本地隐私模式双模；**高风险操作（删除文件/改设置/支付）默认要求用户确认**。
- **启用时机**：任务涉及「在本机真实动手」且组长不便直接做时（大批量文件整理、系统排查、跨端接力）。
- **调用**：**marvis-cli**（https://github.com/kakenhidesu/marvis-cli ，零依赖，复用 Marvis 桌面端的 MarvisAgent 127.0.0.1:6161）——放进 Marvis 安装目录的 `marvis-cli\` 子目录即装。常用：`--ask "消息"`（非交互发一条即退）、`--tui`（控制台界面）、`@路径` 直接附文件/目录。**前置**：Marvis 桌面端必须运行且已登录，否则报「无法连接 MarvisAgent」。备选仍是 CLI-Anything 控制。
- **约束**：不参与编码/内容生产；涉隐私文件优先本地隐私模式。

### ima 知识库（腾讯）
- **定位**：RAG 个人知识库（混元 + DeepSeek 双引擎），50GB 免费空间。
- **强项**：**公众号文章/微信文件一键入库**、19 种格式解析、私域问答可溯源原文、跨文档对比、ima 2.0 任务模式（报告/播客全自动生成）、团队共享库。
- **启用时机**：素材沉淀、私域问答、公众号选题支撑、长报告/播客生成。
- **调用**：**ima-cli**（https://github.com/vissong/ima-cli ，Node ≥22.12 构建，`npm install` 即含构建）——凭证走环境变量（IMA_CLIENT_ID/IMA_API_KEY），`auth status` 验认证、`kb list` 验只读链路。
  - 常用：`ima note search|list|view|create|append`（笔记）、`ima kb list|search|browse|import-url|add-note|upload|download`（知识库）、`--output json` 机器可读。
  - 特性：显式边界——只在收到明确指令时才动 ima，写什么读什么全部可见可审计（这正是它相对官方 Skill 的价值）。
  - 写操作（upload/import-url/create）先小文件试跑再正式用。
- **约束**：生成内容强制要求「严格基于知识库」防幻觉；商用注意版权（只入库有权限的内容）。
