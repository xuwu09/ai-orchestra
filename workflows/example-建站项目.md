【工作流模板】建站项目
- 沉淀日期：2026-09-14
- 来源项目：健身指导网站（fitness-site）

## 任务特征（触发条件）
- 适合：网站类项目（静态站/工具站，file:// 双击可用或本地落盘交付），原生 HTML/CSS/JS
- 不适合：需要后端/数据库的站点（另立模板）；纯落地页一体的轻任务（→ 设计组 Wegic 更快）

## 调用链
顾问组（技术向主笔 ↔ 互审，多轮至最详细版）→ 干活组（落盘到本地项目目录）→ 组长验收（静态+行为）→ 修复循环 → 用户终验

## 各环任务包要点
- 方案环：必须含技术栈禁项（**禁止 fetch 本地 JSON / ES Module / CDN**——file:// 下全部失效）、目录结构、数据结构（data/*.js 全局常量）、逐页功能清单、验收标准
- 制作环：直接落盘不逐文件贴出；写完自测（文件齐全非空、node --check 过语法）；交交付说明.md（完成度对照+问题记录+遗留点，禁止隐瞒）
- 验收环：① node --check 全部 JS ② 正则扫禁项（fetch(/type=module/import /cdn.）③ vm 跑数据文件核对 id/键名与消费方对齐 ④ 无头浏览器 file:// 冒烟查 console ⑤ 逐条过方案验收标准

## 验收要点与坑记录
- 坑：id 校验逻辑与数据/SVG 实际口径不符 → 报错框常驻。规避：校验代码用「数据 id ∩ DOM 实际渲染 id」双向比对写进方案验收标准
- 坑：init 无条件绑定尚未渲染的按钮 → 首次进入即抛 TypeError。规避：方案中要求「事件绑定与元素渲染同生命周期，或绑定前判空」
- 坑：干活组交付说明与实际不符。规避：组长不轻信交付说明，一律亲自实测（铁律）
- 坑：GUI 客户端（积分制/剪贴板接力）做实现产物 bug 密集。规避：实现任务收敛到能落盘+自测的 agent
